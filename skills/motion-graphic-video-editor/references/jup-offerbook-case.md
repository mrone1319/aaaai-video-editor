# JUP Offerbook — 剪辑公式（实测拆解）

> **作者示例案例（第三方品牌，仅作拆解学习）。** 品牌名、Logo、配色与文案均属原品牌方，不可直接套用；可迁移的只是剪辑结构与方法。

> 参考片：`JUP UI Show.mp4`（Jupiter Offerbook 产品发布片）
> 25.771s · 1920×1080 · 29.97fps · 771 帧 · 有音轨
> 拆解日期：2026-08-11 · 全部数值为实测，非目测

> ## ⚠️ 2026-08-12 重大更正
>
> 本文初版结论「零硬切、全靠辉光变形转场」**是错的**，起因是检测命令带了 `-v error`，
> 把 `metadata=print` 的输出整个静默吞掉，于是每个阈值都返回 0 个切点——
> **不是没有切点，是根本没读到数据**。
>
> 用 `metadata=print:file=-` 重测后：本片阈值 0.1 有 **19 个检测点，其中 12 个是真硬切**
> （逐帧亮度单帧跳变 Δ>12，并已抽帧目视确认）。平均每 2.1 秒一次硬切。
>
> 受影响的原始结论：①「零硬切」→ 错；②「白场接管是 blob 长大后反相」→ 错，
> 是**硬切进白场、硬切出白场**；③「单一辉光系统完成所有转场」→ 辉光贯穿全片属实，
> 但它不承担转场，转场靠硬切。下方正文已按实测数据改写。

**一句话定性**：模式 B（柔和产品演示）的高完成度范本，气质极其平滑，
**但平滑感来自辉光系统的视觉连续性，不是来自没有硬切**——实际每 2.1 秒就切一刀。

## 三、拍点纪律（⚠️ 本节结论已于 2026-08-12 大幅下调）

> **第二次更正**：下面这套"正拍 7 / 反拍 8"的分析**大部分是统计噪声**。
> 正拍+反拍网格间距只有 beat/2 = 0.244s，而我当时用 ±0.10~0.12s 的容差——
> 这个宽度下几乎任何时间点都会"落在网格上"。
>
> 而且我当时统计的"事件点"多数取自帧差曲线的能量峰，**那是动画运动的副产品，
> 不是剪辑决策**。真正值得做拍点分析的只有硬切。
>
> 用严格检验（±0.03s，随机期望按网格间距折算）重测本片 12 个硬切：
> **3/12 命中，随机期望 3.0 → 与随机无异。**
> 也就是说 **Offerbook 的硬切并没有系统性地卡在拍上**（虽然个别刀极准，
> 如 7.841s 差 0.007s、11.411s 差 0.013s，但也有差 0.230s 甚至 2.399s 的）。
>
> 详见 [jup-pickapack-case.md 第四节](jup-pickapack-case.md)。
> 下面原始记录保留供参考，但**不要据此写规则**。

### 原始（有缺陷的）分析记录

用 librosa 实测拍位（非假设网格起点）逐个事件比对，**15/16 个事件在网格上，但正拍与反拍
几乎对半分**：

| 落点 | 事件 |
|---|---|
| **正拍（7 个）** | 卡片段 9.11 · **白场接管 10.41** · **白场峰值 11.41** · Fixed terms 16.12 · Money Market 20.55 · Now available 21.86 · **Logo 24.75**（差 0.002s，帧级） |
| **反拍/切分（8 个）** | 标题卡 6.41 · 黑场呼吸 7.84 · Lend 切换 8.78 · 落回 UI 11.68 · 4,000+ 14.15 · P2P 17.45 · Refer 18.45 · URL 药丸 23.59 |

**规律：重点落正拍，过渡与次要信息落反拍。**

- 全片三个最重要的时刻（白场接管、白场峰值、Logo）都**帧级精准落在正拍**（差 0.014–0.062s）。
- 所有转场、次级信息卡、连接段落**一律落在反拍**（差 0.008–0.058s，同样精准，只是落在拍与拍之间）。

另有一条时间维度的规律：**9s 之前没有任何事件落在网格上**（音乐 2.83s 才进，前段完全自由），
**9s 之后才开始锁网格**。即：

> **前 35% 自由呼吸，后 65% 锁拍。**

这条与 skill §5 现有写法"每个视觉事件落在 beat/bar 线上"直接冲突——那种写法产出的是节拍器式
的机械感，正是"AI 感"的一大来源。真实高完成度作品是**有选择地卡拍**。

## 四、核心机制：单一辉光系统贯穿 25 秒

全片只有**一个**径向渐变 blob（绿→青软边光晕），从头到尾变形，兼任背景、转场、光源、图形
四种职能。这是 §3.3 铁律 3"一个贯穿性动态元素兼任四职"的极致执行：

| 时间 | 形态 | 职能 |
|---|---|---|
| 0.6s | 两个 rim-lit 球体 | 背景图形 |
| 1.4s | 底部升起的穹顶 | 环境光 |
| 2.6–6.2s | UI mockup 的边缘 rim light | 产品打光 |
| 6.4s | 标题卡外的辉光环（donut） | 强调框 |
| 9.4s | 卡片队列后方的穹顶 | 背景层次 |
| **10.4–11.4s** | 白场段（**硬切进、硬切出**，见下方更正） | 段落分隔 |
| 16.1s | 同心弧纹（moiré 干涉纹） | 图形纹理 |
| 22.0–23.3s | 两个圆从相切分离到并排 | 图形叙事 |
| **23.6s** | **收缩融合成 URL 药丸**（能看到扇贝状 metaball 融合中间态） | **UI 容器** |
| 24.75s | 收没 → Logo 独自出现 | 退场 |

**⚠️ 原文这里写「白场是 blob 长大后反相、连续形变、零硬切」——经复测是错的。**
实测逐帧亮度：

```
10.377s 亮度 115.2  →  10.410s 亮度 233.5   （单帧 Δ118.4，scene_score 0.887）硬切进白
11.411s 亮度 218.5  →  11.445s 亮度  76.7   （单帧 Δ141.7，scene_score 1.000）硬切出白
```

已抽帧目视确认：11.411s 是白底"On your terms"，下一帧 11.445s 直接是深色笔电 UI，
一帧之间完全换画面，**是标准硬切，不是形变**。

**真正可迁移的结论应该是**：辉光系统贯穿全片带来的是**视觉语言的连续性**
（每一段都由同一套光在打底，所以整体像一个东西），
而**段落之间该切就切**——平滑感来自设计系统统一，不是来自不敢切。

## 六、文字机制

**逐词追加 + 整行重新居中**（全片用了三次，是这支片的签名手法）：
- "Now" → "Now liquid"
- "With" → "With any" → "With any assets" → "With any assets on Solana"
- "On" → "On your terms"

细节：新词进入时整行重新居中（不是左对齐往右长），新词有独立的落位微动（先偏移/不同字重，
再落定对齐）。既有词在新词到达时会提亮（"Now" 从灰变白）。

**关键词上色**：`The Money Market for Everything Onchain.` 中 "Onchain" 用青色渐变，
全片只此一处——比满屏高亮克制得多。

## 八、这支片给 skill 的几条修订建议

1. **§5 拍点规则要改** — 修订版结论：**卡拍与否是逐片选择，不存在"必须卡拍"**。
   本片 12 个硬切与拍位的距离从 0.007s 到 2.399s 都有，统计上与随机无异；
   而 Pick a Pack 的 4 个硬切则 3/4 锁在 ±0.03s 内。
   **真人剪辑里有的刀锁死网格、有的刀完全自由，这种不统一本身就是人味；
   机械地把每一刀吸附到拍线上才是 AI 感的来源。**
   （四支交叉验证，见 [jup-pickapack-case.md 第四节](jup-pickapack-case.md)）
2. ~~§7.5 白溶解改用 blob 反相~~ — **此条已作废**（初版误判，白场是硬切进出）。
   替代结论：**白场段本身值得学**（1 秒纯白 + 黑字，夹在暗调片中间），但实现方式就是硬切。
3. **§6.5 色相漂移可升级为色相弧线**：首尾配比一致的往返，比单向漂移更有"回家"的完成感。
   （注：Gacha 是振荡型、Showcase 无此特征，属单片选择而非家法）
4. **"黑场呼吸"不必是空黑**：这支片的 ~1s 低亮段放的是功能 UI 切换动画（Borrow↔Lend），
   既完成了呼吸，又交付了产品信息，比空黑高效得多。**（3/3 三支全部成立，可写进规则）**
5. **辉光系统贯穿全片**：从背景到 UI 容器由同一套光打底，带来视觉语言的连续性——
   但**它不负责转场，转场该硬切就硬切**。平滑感来自设计系统统一，不是来自不敢切。

## 九、方法论教训（值得写进 §3.1）

初版拆解把「零硬切」当成核心结论，是因为检测命令写成：

```bash
ffmpeg -v error -i in.mp4 -vf "select='gt(scene,0.1)',metadata=print" -an -f null -   # ❌
```

`metadata=print` 默认写 INFO 级日志，`-v error` 直接把它全部压掉 → grep 永远是空 →
误判成「0 个切点」。**这是静默失败，不是空结果**，而且看起来非常像一个干净的结论。

正确写法（显式指定输出到 stdout，并校验收到的帧数）：

```bash
ffmpeg -v error -i in.mp4 \
  -filter_complex "select='gte(scene,0)',metadata=print:file=-" -an -f null - 2>/dev/null
# 必须核对：收到的 scene_score 条数 ≈ 总帧数，否则说明管道断了
```

**通则：任何"结果为 0/为空"的检测，都要先证明管道确实产出了数据，再解读这个 0。**
