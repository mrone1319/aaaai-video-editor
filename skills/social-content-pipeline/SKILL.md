# Social Content Pipeline

## 定位

一条流水线：搜集信息 → 分析角度 → 写文案 → 出图 → 打包成品。
五个环节前后依赖，按顺序执行，不需要复杂的协商机制。

## 能力边界（先说清楚，避免期待落空）

| 环节 | 状态 | 说明 |
|---|---|---|
| 搜集信息 | ✅ 可做 | 网页搜索获取相关信息、竞品动态、热点话题 |
| 分析信息 | ✅ 可做 | 提炼内容角度和受众定位 |
| 整理文案 | ✅ 可做 | 按用户指定的平台分别产出（规格见下方"平台规格表"） |
| 输出图片 | ✅ 可做 | 有设计工具连接器（如 Canva）时可用它出图，需先经用户确认选择，不能未经选择直接调用；**没有连接器也能交付**——见"出图降级方案"。Canva 是可选项，不是前提 |
| 输出视频 | ⚠️ 能力有限，但可打包现成视频 | 不会**生成**视频（没有内建视频生成能力）；但如果用户已经有剪好的成品视频（比如 `aaaai-video-editor` 交过来的 `<项目>/out/final.mp4`，或 motion-graphic-video-editor 渲染的成片），Visual Producer 阶段可以直接把这支视频的路径当作最终视觉资产，配上文案打包进发布包——不需要重新生成图片 |
| 发布到各平台 | ❌ 无法自动完成 | 没有官方发布 API 连接器；可行路径是浏览器自动化模拟操作（每次需用户当场确认）或用户自建的第三方自动化工具（如 Zapier），本 skill 不代替搭建 |

**核心原则：不假装能做到做不到的事。** 视频生成、发布这两项能力有限的地方，如实说明，不编造"已完成"的假象。视频**打包**（不是生成）是可以做的，用户提供现成视频路径时不要以"不做视频"为由拒绝。

## 触发方式

- `/content-pipeline [主题/目标/参考资料]`
- `content pipeline: [主题/目标/参考资料]`
- `启动内容生产线：[主题/目标/参考资料]`

单纯问"最近有什么热点"、"帮我写一条推文"这类单一环节需求，直接回答即可，不需要触发完整流程。

### 从 aaaai-editor 交接过来时

`aaaai-video-editor` 收尾后会用唤醒词开头交接，例如：

```
启动内容生产线：<主题一句话>。成片：<P>/out/final.mp4；封面：<P>/out/cover_1080x1920.png；逐字稿：<P>/work/captions.json；风格：<风格名>；客户：<名>
```

- `客户：<名>` 是**可选**字段：有就直接用它当客户名去找品牌档案，不再重复问"这次是哪个客户"；没有就照常问。
- 成片、封面、逐字稿路径直接当素材：逐字稿是文案的事实来源，封面可直接当配图（见"出图降级方案"）。

## 启动前确认

- **客户**：这次是哪个组织/项目/个人（交接信息里已给 `客户：` 就跳过）
- **主题/目标**：这次内容是为了什么（推广产品/活动、维持账号活跃、回应热点等）
- **目标平台**：**由用户指定**，不默认只做 X/IG——可选 X、Instagram（Reels／贴文）、小红书、抖音、视频号、TikTok、YouTube Shorts、B站等，可多选
- **数量**：要几条内容？默认先做 1-2 条完整成品，不做整月排期
- **风格参考**（可选）：过往内容、品牌调性、竞品风格；没有提供的话先查品牌档案（见下方），都没有再走"首次建档"，不要自行假设一个风格

## 品牌档案与内容归档

这个 skill 会被用于不同的组织/项目方/个人，风格不能混用，需要有地方持久存放每个客户的规范。档案就是本地 Markdown 文件（可以放在 Obsidian 库里，也可以是普通文件夹）。

### 路径（唯一约定）

两个根目录从 aaaai-editor 设置读取：运行 `~/.aaaai-editor/bin/aaaai-editor config`（或直接读 `~/.aaaai-editor/config.json`）里的 `brand_dir` 与 `history_dir`。没有 aaaai-editor 设置档时，默认 `brand_dir = ~/Documents/brand-profiles`、`history_dir = ~/Documents/content-history`。

```
<brand_dir>/<客户名>.md                     # 品牌档案，每个客户一份
<history_dir>/<客户名>/<日期>-<主题>.md      # 内容归档，每次产出一份
```

- 品牌档案：视觉、语气、禁忌、输出语言，模板见下方。
- 内容归档：方便后续查"之前发过什么"，避免重复选题，也能给情报官/分析官做参考。
- 目录不存在时，第一次写入前用 `mkdir -p` 建好即可。

### 启动流程

1. 确定客户名（交接信息里的 `客户：`，或直接问用户）。
2. 检查 `<brand_dir>/<客户名>.md` 是否存在：
   - **存在**：直接读取使用，不再重复询问风格。
   - **不存在**：走下面的"首次建档"。
3. 产出成品后，**自动**归档到 `<history_dir>/<客户名>/<日期>-<主题>.md`，不需要逐次确认。
4. **唯一需要提醒用户的情况**：即将覆盖一份已存在的档案内容（比如同一客户的档案已存在，但这次给出的风格明显不同）——先提示"检测到已有档案且内容有出入，是否覆盖"，避免误删之前积累的规范；单纯新增内容归档不受此限制。

### 首次建档（没有档案时）

一次问完四个问题（Claude Code 用 AskUserQuestion；其他平台在一条消息里列出，见文末）：

1. **主色／视觉**：主色、辅色（HEX 或描述）、视觉风格关键词（简约／插画／3D／复古…）、有没有参考图。
2. **语气**：专业严肃／轻松幽默／悬念挑逗／其他；常用与避免的表达。
3. **禁忌词与硬性规则**：绝对不能出现的词、颜色、话题、必须带的免责声明等。
4. **输出语言**：简体中文／繁体中文／英文／双语／其他——**问清楚，不要默认中文**。

问的同时**告诉用户档案将保存在哪里**（`<brand_dir>/<客户名>.md` 的实际绝对路径），用户回答后再写入，写入后告知"已建档"。

### 品牌档案模板

```markdown
# <客户名> 品牌档案

## 视觉
- 主色：#______ 辅色：#______
- 字体偏好：
- 视觉风格关键词：（如：简约 / 插画 / 3D / 复古）
- 参考图/过往作品链接：

## 语气
- 语气关键词：（如：专业严肃 / 轻松幽默 / 悬念挑逗）
- 常用/避免的表达方式：

## 语言
- 输出语言：（如：简体中文 / English / 中英双语）

## 硬性规则
- 禁忌词：
- 绝对不要做：（如：不用某种颜色、不开某类玩笑、必须带某个免责声明）

## 常用平台
- （如：X、小红书、抖音）

## 更新记录
- <日期>：<变更说明>
```

## 平台规格表

按用户指定的平台逐一产出；表中数值是撰写与出图时的参考上限，平台规则变动时以平台官方为准，并在交付说明里提醒用户发布前复核。

| 平台 | 视觉尺寸 | 文案长度 | 标签 / 话题规则 |
|---|---|---|---|
| X | 横版 16:9（1600×900）或方图 1:1；视频 16:9 或 9:16 | 单条 280 字符（中文约 140 字）；长内容写推文串（首条钩子 + 展开 + 结尾 CTA） | 标签 0–2 个，放句末或不放 |
| Instagram 贴文 | 4:5 竖版 1080×1350（轮播同尺寸），方图 1080×1080 | 说明文字 ≤2200 字符；前 125 字符决定"更多"之前能看到什么 | hashtag 放文末或首条评论 |
| Instagram Reels | 9:16 1080×1920 | 同上，钩子放第一行 | 同上 |
| 小红书 | 3:4 竖版 1080×1440（首图即封面，标题大字压图） | 标题 ≤20 字；正文 ≤1000 字，分段 + 适量 emoji | 话题用 `#话题#` 形式，放文末 |
| 抖音 ／ 视频号 ／ TikTok ／ YouTube Shorts | 9:16 1080×1920，关键内容留在中部安全区 | 描述简短：抖音／视频号一两句 + 话题；TikTok ≤2200 字符；Shorts 标题 ≤100 字符 | 抖音／视频号 `#话题`；TikTok、Shorts 用 hashtag |
| B站 | 横版 16:9 1920×1080，封面 16:9 | 标题 ≤80 字；简介可较长，写清看点与时间轴 | 标签（tag）在投稿页单独填写，不写进正文 |

**标签数量默认上限 5 个**（所有平台通用）：只挑价值最高的，宁缺毋滥；用户明确要求更多时再加。

## 五个环节

### 1. 情报官（Research）
- 搜索主题相关的最新信息、同类账号最近在发什么、有没有可借势的热点
- 关键信息尽量多方交叉确认，标注信息的时效性
- 有 aaaai-editor 交接的逐字稿时，先从逐字稿里取事实
- 产出：3-5 条关键信息点 + 1-2 个可用的角度

### 2. 分析官（Analysis）
- 从情报官的发现里提炼**这条内容该讲什么故事**，明确"钩子"是什么
- 定义目标受众（具体到人群，而不是笼统的"用户"）和适合的语气基调
- 产出：内容角度 + 目标受众 + 语气基调，作为文案官的创作简报

### 3. 文案官（Copywriter）
- 按分析官的简报与品牌档案里的**输出语言**，为每个指定平台分别写出正式文案，遵守"平台规格表"的长度与标签规则（例：X 推文串；Instagram 说明文字 + hashtag；小红书标题 + 正文 + `#话题#`；短视频平台一两句描述 + 话题；B站标题 + 简介 + tag）
- 产出：可直接发布的文字成品，不是选题大纲

### 4. 视觉制作官（Visual Producer）
- 根据定稿文案设计配图方向，图要支撑文案的核心信息
- 按"平台规格表"处理尺寸
- 如果有品牌档案，严格按档案里的配色/字体/风格关键词执行；没有档案且用户也没提供参考，就用简洁、贴合内容主题的通用风格，不擅自套用某种固定美术风格
- **需要视频且是从头剪辑**：超出能力范围，如实告知，不强行用图片工具冒充视频产出
- **需要视频但用户已有现成成片**（`aaaai-video-editor` 交过来的 `out/final.mp4`，或 motion-graphic-video-editor 的成片）：确认文件路径可用，把它当作这条内容的最终视觉资产，跳过图片生成步骤，直接进入打包——这不算"生成视频"，是正常的素材打包

#### 出图降级方案（没有 Canva 等设计连接器时）

先告诉用户：**Canva 是可选的**，没有连接器也能交付。按下面顺序选第一个可用的：

1. **aaaai-editor 封面**：项目目录下的 `$P/out/cover_*.png`（`$P` = aaaai-editor 项目目录，如交接信息里的 `<P>`），尺寸不合适时说明需要哪种比例，让用户用 aaaai-editor 重出对应尺寸的封面。
2. **motion-graphic 海报帧**：motion-graphic-video-editor 交付的海报帧／关键帧 JPG（每支片都至少有一张封面级帧）。
3. **纯文字交付**：只交文案 + 一段具体的配图说明（画面内容、构图、文字压图位置、配色、尺寸），由用户自行出图。

### 5. 发布协调官（Publish Coordinator）
- 打包成**发布就绪包**：每条内容配对应平台的最终文字 + 图片／视频的**绝对路径**
- 如有依据可附上建议发布时间，没有依据就不编造
- 用户要求"发布"时，说明当前可行的路径（浏览器自动化需当场确认 / 用户自建自动化），不能自动批量执行
- 归档到 `<history_dir>/<客户名>/<日期>-<主题>.md`

## 各环节输出质量标准（合格线）

- **情报官**：关键信息避免只依赖单一信源；标注信息新旧；避免只搜到一边倒的正面信息
- **分析官**：角度要具体可验证，不能是空泛套话；受众要精确到人群
- **文案官**：首条/首行文字要能独立成立，不依赖后续内容才看得懂；避免"在...的世界里""让我们一起..."这类明显的模板腔调；文案里的具体数字/事实要能追溯到情报官的发现，不能编造；CTA 保持单一，不要同时塞多个动作；长度与标签数符合平台规格表
- **视觉制作官**：图片要跟文案内容直接相关，不用无关的通用配图；尺寸要匹配平台规格
- **发布协调官**：成品包要完整可用；能力边界要逐条列清楚，不笼统说"已完成"

## 使用边界

- 只是要一条推文，不需要走完整流程 → 直接写，不用触发 pipeline
- 涉及需要**从头剪辑**视频内容（不是已有成品）→ 明确告知能力不足，建议使用 `aaaai-video-editor`（唤醒词 `/aaaai-editor`）或其他专业剪辑工具或人工制作；剪好之后可以再回来交给本 skill 打包发布
- 用户期待"发布"是全自动批量执行的 → 提前纠正预期，发布环节始终需要用户确认

## 在其他平台使用（Codex 等）

本 skill 按 Claude Code 编写；在 ChatGPT Codex 等平台上照下面替代：

- **没有 AskUserQuestion**：启动前确认与"首次建档"的四个问题，一次性在一条消息里列出（每题带编号选项），等用户回复后再继续。
- **没有后台 Bash**：本 skill 不需要长时间任务；如需等待外部生成，用 `nohup … > log 2>&1 &` 启动并轮询日志。
- **没有 SendUserFile**：成品包里的图片、视频、归档文件一律给出**绝对路径**。
- **没有 Canva 等连接器**：直接走"出图降级方案"。
- **HyperFrames 插件只在 Claude Code 可用**：需要讲解片类视频时，告诉用户在 Claude Code 里完成后再交回本 skill 打包。
